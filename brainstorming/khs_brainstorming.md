# khs 브레인스토밍 — 전문가를 위한 DMZ 환경 변화 분석 서비스

> 직접 가기 어려운 DMZ의 환경 변화를 위성으로 찾아, 어디를 더 조사해야 할지 판단할 근거를 제공한다.

현석이 제안하는 기획 방향이다. 기존 앱의 형태나 확보한 데이터의 양에 맞추지 않고, 사용자의 문제에서 출발한다. 아래 기능과 분석 방식은 구현 계획이며, 완성된 기능이나 검증된 성능을 뜻하지 않는다.

## 1. 선택한 타깃과 해결할 문제

**DMZ·접경지역의 생태·환경 연구자와 조사 담당자**를 대상으로 한다. 첫 사용 장면은 하천·습지 주변의 환경 변화를 검토하는 업무로 좁힌다.

현장 접근이 제한되는 지역에서는 필요한 시점마다 직접 관찰하기 어렵다. 이때 담당자가 알고 싶은 것은 “어디에서 변화가 나타났는가”, “그 판단의 근거는 무엇인가”, “어느 구역을 추가로 살펴봐야 하는가”다.

우리 서비스는 위성 관측을 이용해 변화 후보를 찾고, 여러 자료를 함께 검토하여 조사 대상을 선정하도록 돕는다. 숲·수면·토지피복처럼 관측 가능한 환경 변화를 다루며, 실제 담당자가 겪는 업무 부담과 필요한 판단 기준은 확인해야 한다.

## 2. 일반인 대신 전문가를 선택한 이유

일반인 대상은 NASA 데이터의 쓰임을 알리고 DMZ의 자연환경에 대한 관심을 높이는 방향이다. 교육·홍보의 가치는 있지만, 사람들이 자발적으로 서비스를 찾고 계속 이용할 이유까지 설계해야 한다.

전문가 대상은 **“직접 가기 어렵지만, 그곳의 변화에 관한 정보는 필요하다”**는 문제에서 출발한다. 변화 정보를 연구와 조사 계획에 활용한다는 사용 목적도 구체적이다. 이번 기획에서는 이 정보 공백을 줄이는 데 집중한다.

전문가에게 유용한지는 화면의 복잡함보다 실제 업무에서 판단 근거를 얻을 수 있는지로 평가한다. 후보 지역을 찾고 자료를 비교·정리하는 데 도움이 되는지 확인할 수 있다는 점도 이 방향을 선택한 이유다.

민준님 문서의 전문가안은 현장 접근의 어려움과 광학 관측 공백에 주목해 SAR 보조 지도를 제안한다. 우리 안도 관측 공백을 확인하고 여러 자료를 비교하되, **변화 후보 검토, 조사 대상 선정, 검토 기록과 결과 전달**까지 이어지는 사용 과정을 제안한다. 근거: [jmj 브레인스토밍의 아이디어 B](jmj_brainstorming.md).

## 3. 서비스의 핵심 셀링포인트

**변화를 발견한 뒤, 근거를 확인하고, 조사 대상을 선정하는 과정을 한곳에서 연결한다.**

- **살펴볼 지역을 좁힌다.** NISAR 시계열에서 변화 후보의 위치·관측 시기·범위를 찾아 넓은 지역을 검토할 출발점을 제공한다.
- **판단 근거와 관측 공백을 함께 보여 준다.** HLS 광학 영상, 과거 수면 자료, 강수 등을 비교하고 촬영일·품질·결측을 표시한다. 어떤 해석이 가능한지, 무엇을 더 확인해야 하는지 구분한다.
- **결과를 조사 업무에 연결한다.** 전문가가 후보별 의견을 남기고, 추가 검토 목록과 출처가 포함된 결과를 저장해 회의·연구·기존 GIS 작업에 활용하도록 한다.

차별화하려는 지점은 **DMZ 환경 조사에 맞춘 후보 선정과 근거 정리 과정**이다. 기존 위성 뷰어·GIS·분석 제품으로 같은 일을 할 때와 비교해 무엇이 편해지는지 검증해야 한다. 유사 도구가 없거나 우리가 최초라고 주장하지 않는다.

## 4. 어떤 서비스를 만들 것인가

### 첫 분석 주제: 하천·습지의 수면 변화

첫 버전은 수면이 관측되는 범위가 어디에서 늘거나 줄었는지, 그 변화가 여러 관측에서 지속되는지를 살펴보는 웹 분석 도구로 만든다. 위치·면적·관측 시기라는 결과를 정의하기 쉽고, 변화 탐색부터 근거 검토까지 하나의 업무 흐름을 보여 줄 수 있기 때문이다.

예를 들어 임진강 주변을 선택하고 수면 변화 후보를 찾은 뒤, 전후 영상과 강수 자료를 비교해 추가로 검토할 구역을 등록한다. 실제 데모에 쓸 구역·날짜·수치는 자료를 분석하고 대조한 뒤 결정한다.

### 사용자 흐름과 핵심 기능

| 단계 | 사용자가 하는 일 | 서비스가 제공할 것 |
|---|---|---|
| 1. 분석 조건 선택 | 관심 지역과 기간을 선택 | 사용 가능한 관측 날짜와 자료 범위 |
| 2. 변화 후보 탐색 | 지도에서 후보 구역을 선택 | 변화 위치·범위, 최초 관측 시기, 자료 부족 구역 |
| 3. 전후·추이 비교 | 날짜를 바꾸며 이전과 이후를 비교 | 전후 영상, 시계열 그래프, 반복 관측에서의 지속 여부 |
| 4. 근거 검토 | 레이더와 보조 자료를 나란히 확인 | NISAR·HLS 영상, 과거 수면·강수 맥락, 각 자료의 날짜·품질·출처 |
| 5. 조사 후보 선정 | 변화 규모·지속성 등을 비교하고 의견 작성 | 정렬 기준이 보이는 후보 목록, 검토 상태, 추가 확인 사항 |
| 6. 결과 저장 | 선택한 후보와 분석 조건을 저장 | 비교 영상·수치·출처·한계를 담은 보고서, CSV·GeoJSON 등 활용 가능한 자료 |

우선순위는 전문가가 근거를 확인하고 조정할 수 있게 한다. 비슷한 토지피복·계절·관측 조건의 구역끼리 비교해, 논의 계절 변화처럼 정상적인 변화가 단순히 큰 값이라는 이유로 상위에 오르는 문제를 검토한다. 자료가 부족한 곳은 별도 목록으로 구분하며, 우선순위 점수를 재난 발생 확률처럼 표시하지 않는다.

### 화면 구성

지도 중심의 분석 화면을 구성한다. 상단에는 지역·기간·데이터 기준일, 왼쪽에는 변화 후보 목록, 중앙에는 지도와 전후 비교, 오른쪽에는 선택 구역의 근거·품질·메모를 둔다. 하단 시계열에서 날짜를 선택하면 지도 영상과 상세 정보가 함께 바뀌게 한다.

차분한 중립색과 일관된 범례를 사용하고, 변화·선택·결측 상태를 구분한다. 전문가가 수치의 단위와 촬영일을 바로 확인하고, 지도와 그래프에서 같은 구역을 비교할 수 있게 만드는 것이 UI의 우선 목표다.

## 5. 데이터와 분석을 어떻게 연결할 것인가

| 자료 | 서비스에서의 역할 | 해석할 때 구분할 점 |
|---|---|---|
| NISAR 레이더 | 시기별 후방산란을 비교해 변화 후보를 찾는 핵심 자료 | 밝기 차이만으로 수면 변화나 원인을 확정하지 않음 |
| HLS 광학 영상 | 지표 모습과 수면·식생 관련 지표를 확인하는 보조 근거 | 구름·그림자·결측을 제외하고 실제 촬영일을 표시 |
| JRC 과거 수면 자료 | 과거에 물이 자주 관측된 위치와 비교 | 과거 수면 빈도를 현재 수면이나 홍수의 정답으로 사용하지 않음 |
| 강수·지형 등 환경 자료 | 변화의 가능한 설명과 지형적 맥락을 검토 | 강수와 변화가 함께 나타나도 인과관계를 확정하지 않음 |

분석은 다음 순서로 구성한다.

1. **비교 조건 정리:** 관심 구역, 좌표계·격자, 촬영일, 궤도·편파·처리 버전, 결측을 확인한다. 기존 통계의 구역과 분석할 구역이 다르면 다시 집계한다.
2. **변화 후보 계산:** 비교 가능한 NISAR 관측의 후방산란 차이와 시계열을 계산한다. 기준과 임계값을 기록하고, 지형 영향·잡음·관측 조건 차이에 따른 오탐을 검토한다.
3. **수면 여부와 변화 검토:** HLS 및 과거 수면 자료 등으로 후보를 대조한다. 수면 분류 방법과 비교 범위가 검증된 경우에 면적 변화를 제공하고, 그 전에는 레이더 변화 후보로 표시한다.
4. **결과 생성:** 지도용 영상·영역 정보와 구역별 통계, 출처·처리 조건·품질 정보를 함께 만든다. 화면의 표·그래프·보고서가 같은 계산 결과를 사용하게 한다.

충분한 과거 자료가 있으면 비슷한 계절과 비교한다. 자료가 짧으면 ‘선택한 시점 사이의 변화’로 설명한다. 수면 면적과 습지 전체 면적·수위·수질은 서로 다른 값이며, 이 서비스가 제공하는 관측량을 명확히 표시한다.

## 6. 구현 순서와 첫 데모 범위

데이터 처리와 웹 화면을 분리한다. Python으로 분석용 자료와 지도·그래프용 결과를 만들고, 웹 화면은 GeoTIFF에서 만든 표시용 영상과 JSON·GeoJSON 통계를 읽어 상호작용하도록 구성한다. 첫 데모는 분석 결과를 미리 계산해 두고 화면에서 빠르게 비교하는 방식으로 만든다.

| 순서 | 만들 것 | 완료를 확인할 기준 |
|---|---|---|
| 1. 분석 사례 선정 | 한 하천 주변의 구역·기간, 원자료 목록, 품질 확인 | 같은 범위를 비교할 수 있고 관측 공백이 정리됨 |
| 2. 분석 결과 생성 | 변화 후보, 전후 영상, 구역별 시계열, 출처·처리 기록 | 원자료와 계산 결과를 대조하고 후보를 독립 자료 또는 전문가 검토로 확인 |
| 3. 분석 화면 연결 | 지역·기간 선택, 지도, 비교 화면, 그래프, 품질 패널 | 같은 구역·날짜·값이 모든 화면에서 일치 |
| 4. 업무 흐름 완성 | 검토 메모, 후보 목록, 결과 저장 | 한 후보를 발견한 뒤 근거 검토와 결과 저장까지 수행 가능 |

**48시간 안의 첫 목표는 한 지역·한 분석 주제에서 위 흐름을 끝까지 보여 주는 것**이다. 수면 변화 분류가 충분히 검증되지 않으면 후보 검토 수준으로 데모의 주장 범위를 제한한다. 숲·경작지 분석, 임의 영역 업로드, 새 관측 알림은 후속 확장으로 둔다.

자료 수집, 분석 검증, 화면 구현은 각각 완료 상태를 관리한다. 데이터 파일을 확보했다고 변화 탐지나 전문가용 기능이 완성된 것으로 설명하지 않는다.

## 7. 신뢰성과 서비스 효과를 어떻게 확인할 것인가

- **계산 검증:** 영상 정렬, 단위, 날짜, 유효 관측 범위, 표·그래프의 값이 일치하는지 확인한다. 타일 전체의 구름 비율과 실제 관심 구역의 관측 품질을 구분하고, 구름·결측으로 관측 범위가 줄어든 것을 실제 수면 축소로 계산하지 않는다.
- **해석 검증:** 별도의 영상·기존 조사 자료·전문가 검토로 변화 후보를 대조한다. 외부 검증이 부족하면 ‘확정된 변화’가 아닌 ‘검토 후보’로 제공한다.
- **한계 표시:** 관측된 변화와 원인 추정을 구분한다. 유효 화소 비율을 정확도라고 부르지 않으며, 촬영 사이에 발생한 사건의 정확한 시각을 알아낸 것으로 표시하지 않는다.
- **사용자 검증:** 실제 조사 담당자가 후보 선정과 근거 정리에 활용할 수 있는지 확인한다. 기존 업무와 비교해 자료 탐색·정리 시간, 재확인 과정, 결과의 유용성이 어떻게 달라지는지 평가한다.

## 8. 운영진 피드백에 대한 답과 남은 확인 사항

| 검토 기준 | 우리 안의 답 | 추가로 확인할 것 |
|---|---|---|
| 서비스의 필요성 | 접근이 어려운 지역의 변화 정보를 조사 판단에 연결 | 실제 담당자의 업무·정보 수요와 사용 의향 |
| 데이터 신뢰성 | 비교 조건·품질·출처 공개, 보조 자료 대조, 관측과 추정 구분 | 탐지 기준, 오탐, 외부 검증 자료 |
| 기존 서비스와의 차별성 | DMZ 조사 후보 발견부터 근거 정리·결과 전달까지 연결 | 기존 GIS·위성 분석 도구 대비 줄어드는 작업 |
