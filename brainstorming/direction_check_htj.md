# 방향 점검 — 공식 심사 기준으로 본 "레이더로 찍은 DMZ의 한 계절"

작성: htj + Claude, 2026-11-14 저녁. 기준은 `ref/03_nasa_seoul_guide.md`(공식 D-Day 안내 요약)다. 지금 저장소에 있는 것만 근거로 삼았다.

## 결론

**방향은 유지한다.** 다섯 기준 중 Relevance·Creativity·Presentation은 강하고, Validity는 오늘 저녁 보강으로 올라왔다. 약한 곳은 **Impact**(누가 꼭 써야 하나)와 **Validity의 남은 구멍**(PROVISIONAL 자료, 거친 앱 영상판)이다.
기능을 더 만들기보다 **약한 두 기준을 설명과 증거로 메우는 데** 남은 시간을 쓴다. 공식 안내도 "완성 못 한 부분은 설계와 선택의 근거를 보여 주라"고 한다(p32).

## 노릴 만한 서울 특별상 (기준 두 개 조합)

- **Best Storytelling**(Creativity + Presentation): 가장 잘 맞는다.
- **Scientific Excellence**(Validity + Relevance): 오늘 보강한 근거(WorldCover, 창 안 구름, 강수)를 Project Details에 잘 쓰면 노릴 수 있다.
- **Rising Star**(Creativity + Validity): 위 둘을 같이 보여 주면 맞는다.
- Impact가 들어간 상(Visionary Impact, Data Excellence 등)은 지금 근거로는 약하다.

## 규정 때문에 반드시 해야 하는 것 (빠지면 감점 또는 자격 문제)

1. **Use of SI 공개**: 우리 코드와 문서는 AI 코딩 도구(Claude 등)와 함께 만들었다. 규정상 **SI가 만든 코드·데이터는 설명문과 메타데이터에 생성 사실을 표시**해야 한다(p25~26). 제출 페이지 5번 칸과 README에 "어떤 도구를 어디에 썼는지"를 적는다. (커밋 메시지 표기와는 별개다.)
2. **공개 링크**: Final Project 링크는 로그인 없이 열려야 한다. 지금 저장소는 비공개다 → 저장소 공개 + 웹 배포(plan.md 9절).
3. **라이선스**: OSI 라이선스를 정하지 않으면 Apache 2.0으로 배포된다. 팀이 정해 `LICENSE`를 둔다. 데이터 출처 라이선스(OSM ODbL, WorldCover CC BY 4.0, NASA 공개 자료)는 References에 적는다.
4. **영어**: Summary 50~200단어, 데모 영어(영상이면 영어 자막).
5. **NASA 로고 금지**: 브랜드로 쓰지 않는다. 지금 화면 하단의 데이터 출처 표기(NISAR (NASA/ISRO) 등)는 출처 표기라 괜찮다.
6. **출석**: 개인 체크인 5번 중 4번, 팀 미팅 전원 1회.
