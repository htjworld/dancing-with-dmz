원본: `ref/2026- NASA_D-Day.pdf` (53쪽, 서울 운영진 배포). 아래는 우리 작업에 걸리는 규정만 쪽 번호와 함께 뽑은 것이다. 판단이 갈리면 원본을 본다. 원본은 "NASA 최신 공식 가이드가 우선"이라고 적는다(p16).

## 마감과 제출 (p9~p15)

- 제출 기간: **11/14 09:00 ~ 11/15 23:59 KST**. 23:55까지 끝내기를 권장한다.
- 공식 팀 페이지 → Project 탭 → Edit Details에서 쓴다. **Save Progress는 임시 저장일 뿐이고, "Submit for Judging"을 눌러 상태가 "Project Submitted for Judging"으로 바뀌어야 제출된 것이다.**
- 마감 전에는 몇 번이든 다시 제출할 수 있고, 마지막 제출본이 심사 대상이다.
- Lock으로 동시 편집을 막는다. 다른 팀원이 Lock을 풀면 게시 전 변경이 덮어써질 수 있다.

## 제출 항목 (p11, p18~p34)

| 항목 | 규정 |
|---|---|
| 1. High-Level Summary | **영어 50~200단어**. 무엇을 만들었나, 챌린지를 어떻게 푸나, 왜 중요한가 |
| 2. Project Demo | 공개 링크 **하나**. **슬라이드 7장 이하(제목 포함) 또는 영상 30초 이하**. 영어(영상은 영어 자막). 로그아웃 상태에서 열리는지 확인 |
| 3. Final Project | 최종 결과물 공개 링크(웹사이트, 코드 저장소 등). 로그인·권한 요청 없이 열려야 한다 |
| 4. Project Details | 무엇을, 어떻게, 왜. 도구·언어·소프트웨어. 문제 정의 → 근거 → NASA 데이터의 의미와 쓰임 → 검증·개선 → 한계와 다음 검증 |
| 5. Use of SI | SI = AI 도구. **어떤 도구를 어디에 어떻게 썼는지 공개.** SI가 만든 이미지·영상은 눈에 보이는 워터마크, **SI가 만든 코드·데이터는 설명문과 메타데이터에 생성 사실 표시** |
| 6. Space Agency Data | 쓴 NASA 데이터와 쓰는 법. **글로벌 상 자격: 챌린지 Resources 탭의 NASA 자료 최소 하나** |
| 7. References | 데이터·도구·코드·문장·이미지 전부 출처·링크·라이선스와 쓰인 곳 |

- 원 작업물은 자유 이용 또는 OSI 오픈소스로 공개한다. 라이선스를 정하지 않으면 NASA가 **Apache 2.0**으로 배포한다(p29).
- NASA 로고를 팀·프로젝트 브랜드로 쓰거나 NASA 보증을 암시하지 않는다. AI 생성물에 NASA 브랜드 요소를 넣지 않는다(p22, p26).
- 18세 미만의 이름·목소리·모습은 넣지 않는다(p22).
- 이틀 안에 완성하기 어렵다는 걸 심사위원도 안다. **완성 못 한 부분은 설계와 선택의 근거를 보여 준다**(p32).
- README 권장: 맨 위에 실행 중인 서비스 링크, 화면 캡처, 실행 순서, 환경변수, 미구현 기능과 알려진 한계. 비밀키는 올리지 않는다(p33).

## 자격 (p30~p31)

- 팀원 전원이 같은 Seoul Event에 확정 등록되고 공식 팀 페이지에 있어야 한다. 마감 뒤 팀원 추가 불가.
- 최종 제출 시 동의 체크 두 개: Terms and Conditions, Confirm All Work is Original(외부 자료는 데이터 칸에 모두 적었다는 확인).

## 서울 출석 (p36~p40)

- **개인 체크인 5번 중 4번**(팀 미팅이 1번을 대신함). 설문 링크는 각 시간대에 Zoom에서 공지한다.
  - 11/14: 11:00~12:00, 16:00~18:00, 19:00~22:00
  - 11/15: 06:00~12:00, 15:00~20:00
- **팀 미팅 1회, 전원 참석, 10~15분, 카메라 켜고.** 대표가 예약한다. 현재 단계 하나만 준비한다. 우리는 "제작" 단계로, 대표가 결과물을 짧게 보여 주고 각자 "직접 한 작업 / 다음 작업"을 답한다.
- 수료증 = 공식 제출 + 서울 출석 둘 다(p50).

## 심사 (p45~p48)

- 심사위원: 박성홍(한국천문연구원), 유원두(AWS 우주위성), 박현우(서울대 데이터사이언스대학원), 이수경(연세대 컴퓨터과학). 과학·데이터·클라우드·CS 배경이다.
- 다섯 기준(공식 페이지와 링크된 제출물을 본다):

| 기준 | 보는 것 |
|---|---|
| Impact | 문제의 중요성과 기대 효과 |
| Creativity | 새로운 접근과 독창성 |
| Validity | 과학적 근거와 방법의 타당성 |
| Relevance | 선택한 챌린지와 해결책의 연결 |
| Presentation | 설명과 시각 자료의 명확성 |

- 서울 시상: 최우수 3팀(종합 1~3위), 우수상(4~10위 중 1~7팀, 글로벌 추천), 부문별 특별상 10개(기준 두 개의 조합, 순위 없음).

| 특별상 | 조합 |
|---|---|
| Rising Star | Creativity + Validity |
| Tech Innovator | Creativity + Relevance |
| Visionary Impact | Creativity + Impact |
| Best Storytelling | Creativity + Presentation |
| Scientific Excellence | Validity + Relevance |
| Impact Maker | Validity + Impact |
| Research Communication | Validity + Presentation |
| Data Excellence | Relevance + Impact |
| Challenge Communication | Relevance + Presentation |
| Inspiring Impact | Impact + Presentation |

- 동점이면 팀 참가가 우선이고, 팀끼리는 팀원이 많은 쪽이 우선이다.
